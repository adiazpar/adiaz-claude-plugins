# Review Shared Memory

Shared memory is proposal-only operational recall, never empirical evidence.

## Inspect One Proposal

Read the exact file under `.re-discipline/memory/proposals/`, the memory index,
relevant accepted topics, linked durable sources, and knowledge governance.
Confirm pending proposals are excluded from ordinary orientation, search, and
context packs. Stop and report a policy defect if one is visible as accepted
recall.

Check duplication, conflicts, project scope, reuse, secrets or machine-local
values, authority leakage, durable links, and expiry. Prefer a concise pointer
over copied source text. Unsupported empirical content remains pending or is
rejected; it is never laundered through memory.

## Obtain And Apply An Explicit Decision

Present an `accept` or `reject` recommendation and require the user's exact
decision. Do nothing when it is missing or ambiguous.

On acceptance, distill only approved recall into a focused topic, label it as
recall, record sources and re-verification conditions, update the index, and
verify memory-tier retrieval before removing the proposal.

On rejection, record the reason as a manager decision event linked to the
originating campaign or run. If no campaign owns it, record the decision in
the memory index. Remove only the exact proposal after the disposition is
durable.

Never edit host-native memory stores, change retrieval profiles, project
truth, or copy raw conversations. Truth admission occurs only during campaign
closure.

Do not commit unless the user explicitly asks.
